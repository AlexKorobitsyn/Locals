# Справочник городов GeoNames

Города хранятся в PostgreSQL и выдаются существующим API
`GET /api/v1/cities?q=Екатеринбург&limit=20&offset=0`. Поиск пользователя
не обращается к внешнему сервису. Импорт запускается отдельным процессом.

## Источник и поля

Источник: [GeoNames](https://www.geonames.org/), данные под
[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Ссылка на источник есть рядом с выбором города в интерфейсе.

Используются файлы из [официальной выгрузки](https://download.geonames.org/export/dump/):

- `cities1000.zip`: населённые пункты с населением больше 1000 и часть
  административных центров; выбираются коды PPL, PPLA, PPLA2–4 и PPLC.
- `admin1CodesASCII.txt`: связь населённого пункта с регионом.
- `alternatenames/RU.zip`: русские названия городов и регионов.

По умолчанию импортируется Россия (`--country RU`), названия — на русском
(`--language ru`). Предпочитаются preferred-названия; исторические и
разговорные варианты с соответствующими флагами исключаются. Если перевода
нет, используется основное название GeoNames.

Сохраняются `geoname_id`, `name`, `region`, `country` (ISO-код), `lat`, `lng`,
`timezone`. Часовой пояс проверяется через IANA/ZoneInfo. Это справочник
населённых пунктов, а не полный перечень всех официальных городов и деревень.

## Идентификаторы и повторный импорт

- `cities.id` остаётся внутренним ID; внешние ключи пользователей, артистов
  и площадок продолжают ссылаться на него.
- Nullable-поле `geoname_id` уникально. Повторный импорт обновляет ту же
  запись, даже если GeoNames изменил название или координаты.
- Если ручная запись однозначно совпадает по названию, региону и стране,
  ей присваивается внешний ID без пересоздания. Для России распознаются
  также ручные значения страны «Россия», «Russia», «RUS».
- Неоднозначные ручные записи автоматически не объединяются. Исчезнувшие
  из выгрузки города не удаляются: они могут использоваться в приложении.
- Разные населённые пункты одного региона иногда имеют одинаковые названия.
  Они сохраняются раздельно по `geoname_id`. Уникальность ручных записей
  контролируется отдельным частичным индексом.
- Импорт проходит одной транзакцией; параллельные импорты сериализуются
  PostgreSQL advisory lock. Ошибка БД откатывает изменения этого запуска.

Миграция `0007_geonames_cities` добавляет внешний ID и меняет ограничение
уникальности. Откат к прежней схеме не удаляет данные автоматически: если
после импорта есть одноимённые записи, сначала потребуется разрешить их
конфликт с прежним ограничением.

## Запуск в Minikube

Из корня проекта собери актуальный backend-образ:

```bash
eval "$(minikube -p minikube docker-env)"
docker build -t locals-backend:k8s .
eval "$(minikube -p minikube docker-env -u)"
```

Создай одноразовый Job:

```bash
city_job=$(kubectl create -f k8s/cities/import-job.yaml -o name)
kubectl -n locals wait --for=condition=complete "$city_job" --timeout=300s
kubectl -n locals logs "$city_job" -c import-cities
```

Init-контейнер Job сначала выполняет `alembic upgrade head`, основной
контейнер — `python -m APP.import_cities --country RU`. Настройки БД
поступают из существующих ConfigMap и Secret; данные GeoNames скачиваются
по HTTPS. После завершения Job автоматически удаляется через час.
Для повторного запуска используется та же команда `kubectl create`:
`generateName` создаёт новое имя Job.

Затем обнови backend Deployment:

```bash
kubectl -n locals rollout restart deployment/app
kubectl -n locals rollout status deployment/app --timeout=180s
```

При первой установке миграция должна выполниться до запуска нового
backend: новая модель читает колонку `geoname_id`.

Если Job завершился ошибкой, посмотри его Pod и оба контейнера:

```bash
kubectl -n locals get pods -l job-name="${city_job#job.batch/}"
kubectl -n locals logs "$city_job" -c migrate
kubectl -n locals logs "$city_job" -c import-cities
```

## Запуск вне Kubernetes

Используется то же окружение, что у backend: зависимости из requirements,
`DATABASE_URL`, `JWT_SECRET_KEY` и остальные настройки приложения.

```bash
alembic upgrade head
python -m APP.import_cities --country RU --data-dir /tmp/locals-geonames
```

Опции:

- `--dry-run`: скачать и проверить исходники, не менять БД.
- `--refresh`: заново скачать файлы вместо использования локального кэша.
- `--country RU --country BY`: добавить несколько стран.
- `--language ru`: предпочитаемый язык названий.
- `--data-dir PATH`: расположение исходников и кэша загрузки.

Уже скачанные файлы используются повторно. Чтобы обновить их, добавь
`--refresh`. Для своего зеркала задай `GEONAMES_BASE_URL`; таймаут HTTP
настраивается через `GEONAMES_DOWNLOAD_TIMEOUT_SECONDS` (по умолчанию 60).

CLI пишет JSON-логи с числом созданных, обновлённых и неизменённых записей.
`matched_manual` показывает, сколько существующих ручных записей привязано
к GeoNames; эти записи также входят в число обновлённых.

## Проверка в приложении

При работающем frontend port-forward:

```bash
curl -fsS --get http://localhost:8080/api/v1/cities \
  --data-urlencode 'q=Екатеринбург' --data-urlencode 'limit=5'
```

Ожидается город с регионом «Свердловская область», координатами и timezone
`Asia/Yekaterinburg`. В форме артиста, профиля или события введи название
в поле «Город» и выбери «Екатеринбург · Свердловская область» из подсказок.
Название с регионом сохраняется в выборе и при редактировании, когда
город отсутствует на первой странице списка.

Для обновления frontend после изменения компонента выбора:

```bash
eval "$(minikube -p minikube docker-env)"
docker build -t locals-frontend:k8s ./frontend
eval "$(minikube -p minikube docker-env -u)"
kubectl -n locals rollout restart deployment/frontend
kubectl -n locals rollout status deployment/frontend --timeout=180s
```

После пересоздания Pod перезапусти его port-forward, если соединение оборвалось.

## Одно поле с подсказками

При вводе названия под полем «Город» появляется список: город, регион, страна.
Отдельного select больше нет. Можно выбирать мышью или стрелками и Enter,
Escape закрывает список, крестик очищает выбранный город. Для обязательного
поля одного набранного названия недостаточно: нужно выбрать запись из справочника.
Поиск использует PostgreSQL и существующий `/api/v1/cities`, с задержкой 250 мс
после ввода. Нажатие «Ещё города» загружает следующую страницу подсказок.

## Адрес по клику на карту

В форме площадки выбранная точка сразу заполняет координаты. Через 500 мс после
последнего клика frontend вызывает защищённый `GET /api/v1/geocoding/reverse`
с `lat` и `lng`. Backend обращается к Nominatim/OpenStreetMap и заполняет
адрес вида «Екатеринбург, улица Малышева, 1». До завершения поиска кнопка
сохранения отключена. Ручная правка адреса отменяет применение ответа;
запоздавший ответ от старой точки не заменяет адрес новой.

Nominatim находит адрес ближайшего подходящего объекта OSM: результат нужно
проверить и при необходимости исправить. Если адрес не найден или сервис
недоступен, координаты сохраняются, адрес можно ввести вручную или повторить
поиск. Смена города сбрасывает старую точку и адрес. При редактировании уже
сохранённый адрес самопроизвольно не перезаписывается.

Публичный Nominatim подключён по согласованию для учебного приложения.
[Политика использования](https://operations.osmfoundation.org/policies/nominatim/):
максимум 1 запрос в секунду на всё приложение, идентифицирующий User-Agent,
атрибуция OpenStreetMap, умеренное использование по действию пользователя.
Городские подсказки к Nominatim не обращаются. Координаты выбранных публичных
мест отправляются внешнему сервису; секреты и данные аккаунта не передаются.

Миграция `0008_geocoding_cache` создаёт общий кэш PostgreSQL. Короткая advisory
lock и сохранённое время попытки обеспечивают единый лимит для всех реплик.
Время попытки фиксируется до HTTP: ошибки и отмена не обходят лимит. Во время
обращения к провайдеру соединение БД не занято. Ключ включает провайдера, язык
и координаты с точностью до пяти знаков. Успешный ответ хранится 30 дней,
неудачный или пустой — 30 секунд. При превышении лимита API отвечает `429`
с `Retry-After`; frontend делает не более двух повторов с паузой 2,1 секунды.

Настройки через env:

| Переменная | Значение для локального запуска |
| --- | --- |
| `GEOCODING_REVERSE_URL` | `https://nominatim.openstreetmap.org/reverse` |
| `GEOCODING_USER_AGENT` | `Locals/1.0 (+https://github.com/AlexKorobitsyn/Locals)` |
| `GEOCODING_TIMEOUT_SECONDS` | `5` |
| `GEOCODING_REQUEST_INTERVAL_SECONDS` | `1.1`, минимум `1` |
| `GEOCODING_CACHE_TTL_SECONDS` | `2592000` |
| `GEOCODING_FAILURE_TTL_SECONDS` | `30` |

Пустой `GEOCODING_REVERSE_URL` отключает внешний поиск, ручной ввод остаётся.
Провайдера можно заменить без изменения кода на Nominatim-совместимый сервис,
для которого соблюдаются собственные условия использования. Перед запуском
новой версии нужно выполнить `alembic upgrade head` отдельным процессом.
