# Первые рекомендации: rules_v1

`GET /api/v1/recommendations/tracks?limit=20&offset=0&playable_only=false`
публичен. С Bearer-токеном он использует личные предпочтения, без токена -
общий рейтинг. Некорректный или отозванный токен возвращает `401`.
Ответ содержит `items`, `total`, `limit`, `offset`, `mode`, `algorithm_version`.
`Cache-Control: no-store` защищает персональную выдачу от общего HTTP-кэша.

## Выбор кандидатов

Для авторизованного пользователя исключены:

- треки с любой его оценкой;
- треки, которые он лайкнул;
- загруженные им треки;
- треки с участием принадлежащего ему артиста, включая импорт без uploader.

Оценённый альбом или артист служит сигналом вкуса; отдельные неизвестные треки
этого альбома или артиста остаются кандидатами. Если кандидатов нет, возвращается
пустая страница. Уже знакомая музыка автоматически не добавляется обратно.

`playable_only=true` оставляет треки с прикреплённым готовым аудиофайлом.
По умолчанию в выдаче есть также карточки каталога без аудио, с `is_playable=false`.
При построении очереди плеера фронтенд запрашивает `playable_only=true`.

## Жанры и личные сигналы

Жанры трека выбираются по приоритету:

1. Собственные `track_genres`, если они есть.
2. Жанры альбома, если собственных нет.
3. Объединение жанров участвующих артистов, если нет первых двух источников.

Один жанр учитывается один раз независимо от числа артистов и их ролей.
Для рейтингов альбомов и артистов используются собственные жанры этих сущностей.

Для каждого жанра `g`:

```text
F(g) = 1, если жанр выбран любимым, иначе 0
A(g) = среднее(value - 3) по личным оценкам музыки этого жанра
A(g) = 0, если подходящих оценок нет
```

`A(g)` находится в диапазоне [-2, 2]. Оценка 3 нейтральна, высокие оценки
повышают интерес, низкие - понижают. Лайк исключает знакомый трек из кандидатов;
он не подменяет числовую оценку. Оценки площадок не влияют на музыкальные жанры.
Вес роли пользователя влияет на общий Bayesian rating, личные оценки при
вычислении его вкуса учитываются одинаково.

Любимые жанры: `GET /api/v1/me/favorite-genres` и
`PUT /api/v1/me/favorite-genres` с `{ "genre_ids": [1, 2] }`.
PUT полностью заменяет список, `[]` очищает его. До 100 уникальных существующих ID.
Проверка существования, изменение связей и приватный `EventLog` выполняются
в одной транзакции. Повтор одинакового списка не создаёт новых событий.

## Итоговый балл

Для трека с набором жанров `G`:

```text
favorite_genre_score = W_favorite × среднее(F(g) для g в G)
rated_genre_score    = W_rated × среднее(A(g) для g в G)
quality_score        = W_quality × (B - 1) / 4
score.total          = сумма трёх составляющих
```

Если жанров нет, первые два слагаемых равны нулю. Для музыки без оценок
`B = RATING_PRIOR_MEAN`; публичное `rating_avg` при этом остаётся `null`.
Для оценённой музыки `B` - существующий Bayesian rating:
`(rating_sum + C × M) / (rating_weight + C)`.

Настройки env:

| Переменная | По умолчанию | Назначение |
| --- | ---: | --- |
| `RECOMMENDATION_FAVORITE_WEIGHT` | 2 | Бонус любимым жанрам |
| `RECOMMENDATION_RATED_WEIGHT` | 1 | Влияние личных оценок |
| `RECOMMENDATION_QUALITY_WEIGHT` | 1 | Влияние общего рейтинга |

Баллы жанров усредняются: большое число жанров само по себе не даёт бонуса.
Например, новый джазовый трек при любимом jazz, средней личной оценке jazz = 5
и отсутствии общих оценок получает `2 + 2 + 0.5 = 4.5`.

Порядок: `score.total DESC`, `ratings_count DESC`, `track.id ASC`.
Это обеспечивает устойчивые страницы при равных баллах. Личные сигналы
фиксируются для одного запроса; их замена и изменение оценок влияют на следующий.
Если любимых жанров и ненулевых личных сигналов нет, `mode=popular`, иначе
`mode=personalized`. Приоритет жанров и порог нейтральной оценки - правила
`rules_v1`; существенную смену формулы нужно отразить в версии алгоритма.

## Объяснение карточки

Карточка включает поля `TrackRatedShort`, артистов, эффективные жанры,
`matched_favorite_genres`, `genre_preferences`, `is_playable` и `score`.
В `genre_preferences` видны жанр, личный сигнал `affinity` и число оценок.
Это личные сведения посетителя; оценки или предпочтения других аккаунтов
в этот блок не попадают.

`reasons` содержит машинные коды для подписей фронтенда:

| Код | Подпись |
| --- | --- |
| `favorite_genres` | Совпадает с вашими любимыми жанрами |
| `high_rated_genres` | Вы высоко оцениваете музыку этих жанров |
| `low_rated_genres` | Низкие оценки жанра уменьшили балл |
| `community_rating` | Учтён рейтинг слушателей |
| `catalog_fallback` | Подборка каталога без достаточных личных сигналов |

## Следующие изменения после измерений

Первая версия сортирует кандидатов в PostgreSQL, не загружая весь каталог в Python.
Личные жанры и объяснения выбранной страницы читаются ограниченными запросами.
Новых таблиц, миграций, Redis и фонового пересчёта не требуется.

Сначала измерять время SQL и число кандидатов на реалистичном каталоге, сохранять
версию алгоритма при оценке качества. Если сортировка становится дорогой -
проверить `EXPLAIN (ANALYZE, BUFFERS)` и индексы, затем рассмотреть готовый список
кандидатов или кэш с явной инвалидизацией по оценкам и жанрам. Фоновые задачи
понадобятся при измеренно долгом пересчёте или конвертации аудио.
